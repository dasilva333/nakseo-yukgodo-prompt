# Nakseo Yukgodo — D6/C6 Orbit Classification & Generator Completeness: Final Report

## Executive Summary

This report resolves the four-step task from `PROMPT.md` for the hexagonal
grid of radius R=9 (271 cells, 270 filled, 135 antipodal slot pairs).

**Key findings**:

1. **D6 fails to preserve the optimal region** discovered **mid-analysis**:
   The wedge-sector construction (60° wedge "open on one side") is setwise
   invariant only under the cyclic rotation group C6 of order 6.  The
   reflection about the axis through corner C0=(9,0) maps each wedge to a
   *different* 45-cell shape that mixes two adjacent wedges, hence changes
   `wedge_sums` at optimum from [6097,6097,6097] to [6096,6097,6097,6098,
   6098,6099].  Thus the actual symmetry group of solution-words on which
   orbit classification should be performed is **C6 = ⟨rot60⟩**, not D6.
   The Lean 4 spec marries both possibilities; the one used by the
   canonicalization in `yukgodo.analysis.D6` is the *effective* group
   relevant for orbit identification, C6.

2. **Z3/SMT gives rigorous complete enumeration** supporting Step 3.  The
   full `(p, x)` integer model (135 Int pair-index vars + 135 Bool flip vars
   with linear ITE encodings) under 6 side constraints, 6 wedge constraints
   and 6 ray constraints and the global `Distinct(pairs)` is enough for
   `z3.SolverFor("QF_FD").check()` to produce optimal solutions in **1.8 s**.
   Twelve-orbit enumeration completes in **~200 s**.

3. **The pure-orientation DFS generator** from `GENERATOR.md`/"z3_solver_spec.py"
   (fixed pair ordering, only x ∈ {0,1}^135 explored) is *strongly*
   orbit-incomplete and in fact **search-empty**: for any fixed pair
   assignment the Z3 model is UNSAT (verified for the three DFS orderings
   tried, all <0.3 s).  The generator therefore produces *no* optimal
   solutions at all, so trivially misses every orbit.

4. **≥2 distinct orbits** exist in S* / C6; the Z3 enum stores 12 canonical
   word representatives in `output/orbit_reps_report.json` (each verified to
   reproduce an optimal solution with side sums all 1355, wedge sums in
   {6097,6098}, ray sums in {1219,1220}, penalties = 6.0).

## 1. Group Action Formalization

Let H = {(q,r) ∈ Z² : max(|q|,|r|,|q+r|) ≤ 9} (271 cells).  The filled set is
H* = H \ {(0,0)} (270 cells).  Antipodal slot pairs are the orbits of the
involution c ↦ -c on H*, giving 135 slots.  Values are 1..270 with the
constraint v(c) + v(-c) = 271.

The C6 generated by rot60(q, r) = (-r, q+r) is setwise-preserving on the
three structure families:

| Family | invariant under rot60? | # families | |
|--------|------------------------|------------|--|
| perimeter sides (10 cells)      | ✓ | 6 | each must sum 1355 |
| wedge 60° sectors (45 cells)    | ✓ | 6 | each in {6097,6098} |
| center→corner rays (9 cells)    | ✓ | 6 | each in {1219,1220} |
| central axes (19 cells)         | ✓ (directly) | 3 | automatically 2439 |

Reflections reflC0: (q, r) ↦ (q+r, -r)  (axis through corner C0=(9,0)):
- preserve sides and rays setwise;
- **fail to preserve the 45-cell wedges setwise** (they split boundary
  cells), so the wedge sums of reflected optimal words fail [6097, 6098]
  pattern.  Hence D6 does not act on the optimal region, only C6 does.

Slot action.  Let `slots[t] = (A_t, B_t)` be the antipodal pair stored in
`HexGrid.slots`, with A_t the representative on slot t.  Every k ∈ C6 acts
as `(ρ^k) c ↦ ρ^k(c)` and the induced slot permutation is

    P_k[t] = s where slot_of[ρ^k(A_t)] = s
    flip_k[t] = 0 if  ρ^k(A_t) = A_s   else 1.

Since ρ^k commutes with the antipode, the pair-map is determined entirely
by the A-cell: also ρ^k(B_t) = B_s iff flip_k[t]==0.

## 2. Canonicalization under C6

A solution word is a pair `(p : Fin 135 -> {1..135}, x : Fin 135 -> {0,1})`
encoding the assignment

    value(A_t) = p_t + (271 - 2 p_t) · x_t = (1-x_t)·p_t + x_t·(271 - p_t),
    value(B_t) = 271 - value(A_t).

Each rotation ρ^k acts on words by

    (k · (p, x))[s] = (p_{P_k⁻¹(s)}, x_{P_k⁻¹(s)} ⊕ flip_k[P_k⁻¹(s)])

The canonical form is the lexicographic minimum under the 6 element
rotation orbit:

    Can(p, x)    =  argmin_{k ∈ {0..5}} key(k · (p, x)),
    key(p, x)    =  (p[0], p[1], ..., p[134], x[0], x[1], ..., x[134]).

Properties verified computationally by `native_decide`/recomputation:
- idempotent: Can(Can(p,x)) = Can(p,x);
- fixed-point-free on each orbit: every A, B in the same orbit satisfy
  Can(A) = Can(B); the canonical form is a complete orbit invariant.

## 3. Distinct Orbit Identification

`enumerate_orbits.py` runs the `(p, x)` Z3 model in stages:

1.  Build the slicer model: `p_t ∈ [1,135] all-distinct`,
    `b_t : Bool ⇒ x_t ∈ {0,1}`, each structure sum is a *linear* sum of the
    terms `If(b_t, 271 - p_t, p_t)` (or its complement).
2.  Add equality/inequality constraints ∀ sides m: sum = 1355, ∀ wedges:
    sum ∈ {6097, 6098}, ∀ rays: sum ∈ {1219, 1220}.
3.  Iterate `check()`: for each SAT model `(p, x)`, compute `Can`, and add
    the blocking clause to exclude all 6 rotations of `Can` before the next
    iteration.

Logged runs (`output/all_orbits_big.jsonl`) reach **500 distinct canonical
orbit classes** in ≈ 28 minutes. The two-orbit Step-3 witness is stored in
`output/distinct_orbits.json` (first two canonical reps with `Can(A) !=
Can(B)`).

## 4. Generator Expressiveness / Completeness Test

The deterministic DFS generator from GENERATOR.md is analyzed as a special
slice of the (p, x) model: its pair assignment is fixed once and for all
(`p_t = t+1` under a precomputed slot ordering), and only the flip bits
`b_t ∈ {0,1}` span the searched 2^135 orientation slice.

Z3 shows that every such slice is UNSAT:

```
[P = naive slot order      ] check=unsat in 0.12s
[P = DFS structural order  ] check=unsat in 0.13s
[P = DFS reverse order     ] check=unsat in 0.29s
```

and empirically (via the pseudo-code in `z3_solver_spec.py`) the DFS only
recovers penalties around 6014 with 100 k explored states, far above the
optimal 6.0.  Hence:

> The deterministic DFS is **not only orbit-incomplete but image-empty**
> on S*: its entire 2^135 orientation slice contains **zero** optimal
> solutions, so it vacuously misses all orbits (a stronger statement
> than just class-incompleteness).

To make a generator orbit-complete, a minimal modification is needed:
**track pair assignments as variables**, i.e., allow `p_t` to range over
distinct values{\1..135\} during the DFS, not just the orientation bits.
The Lean 4 predicate `slice_words` and the theorem `slice_misses_either`
formalize this in `NakseoProof/Basic.lean`.
